# 输入与工作流

## 接收材料

先从已有文件或文本中提取信息，不要求用户重新填写已经提供的内容。通用输入为：

```text
【任务】：整稿 / 指定章节 / 修改 / 图表与图注 / 审稿回复 / 投稿前检查
【研究问题与动机】：研究对象、问题、重要性与待解决的空白
【方法】：输入输出、关键步骤、假设、理论或实验设置
【结果】：原始或汇总数据、指标定义、单位、对照条件、不确定性
【图表】：图表本体、编号、图注、关联结果和数据来源
【参考文献】：作者提供的条目、DOI、引用键或可读取的全文
【目标期刊要求】：期刊名称、作者指南、文章类型和篇幅限制（如有）
【已有草稿】：需要保留或修改的内容（如有）
【审稿意见与修改记录】：逐条意见、实际完成的修改和定位信息（如有）
【语言与交付】：默认英文正文、中文说明；默认在对话中输出 Markdown
```

任务不同，必需材料不同。方法写作需要真实步骤和设置；结果写作需要真实结果及指标含义；引言需要研究问题、贡献和相关工作；摘要需要能够支撑其陈述的整篇研究信息；返修需要原意见及修改证据。

能读取的文档先实际读取。打不开的附件或无法查看的图片应说明访问限制，不声称已审阅。仅有文件名、摘要或图注不能证明已核对全文、原始数据或图像质量。

## 整理事实与缺口

为影响结论的关键主张记录简短证据定位：文件和章节、页码、图表号、数据记录或文献引用键。只在复杂整稿、争议事实或用户要求时输出完整对应表，普通单段修改无需附大型表格。

- **已核对**：当前确实读取的材料能够支持该主张；注明核对范围。读取汇总表不等于复现统计或实验。
- **作者提供，待核验**：可作为作者报告内容组织草稿，但不能写成助手已验证的事实。
- **解释或假设**：采用 may、might、is consistent with 等与证据强度相符的表达，指出替代解释或验证需要。
- **缺失或冲突**：正文使用 `[MISSING: ...]`，中文说明来源与待解决信息。不能把冲突数据平均、择优或凭叙述强行统一。

只有设想时可以做提纲、研究问题和拟开展方法的表达，不生成虚构的完成式 Results。部分材料足以支持的章节可以先写，其余标缺口。

## Flash 与 Pro

**Flash**：适用于范围明确的快速起草或修改。整理必要事实 → 写所需文本 → 核查事实、引用和措辞 → 输出正文与必要说明。

**Pro**：适用于整稿或跨章节重组。

1. 根据已有材料明确一句话主张，连接“研究问题 → 空白 → 方法 → 结果 → 贡献”，并给出简短章节提纲。空白缺少文献支持时先作为待验证定位。
2. 先写方法，再写结果与讨论，再收束结论；据此定稿引言，完成主体后提炼摘要与标题。文献阅读与核对贯穿各阶段。方法优先和摘要后写来自笔记；将引言定稿及全文检查安排到相应阶段属于本项目编排。
3. 对每个主要结果关联图表或证据，区分发现、解释、局限和后续研究。
4. 检查章节间指标、样本、符号、单位、方法名、贡献和引用是否一致；按期刊要求调整显示结构。
5. 输出论文草稿，再附简短中文说明、材料缺口及尚未完成的核验。正文中保留与缺口对应的英文标记。

仅在用户明确要求早期摘要时，才依据现有真实材料生成标为“暂定草稿”的版本，并保留结果缺口；主体完成后重新核对。此分支不替代默认写作顺序。

没有指定文章类型时，默认原创研究论文，并按材料区分理论、实证或工程研究。不强求每篇论文都同时包含理论推导、模拟和实体实验；不把这套结构直接强加给系统综述、临床试验等有专门报告要求的文章。

## 引用和期刊要求

保留作者已有的引用键或编号及对应关系。作者提供的条目可以保留在 References 中，但未经核验的真实性和支持范围放在中文说明中列明。正文没有可用来源时使用 `[MISSING: source supporting this statement]`。

若实际可用工具允许核验，优先读取期刊作者指南、出版社文章页、DOI 记录及可取得的原文。题录匹配只能核对书目信息，不能证明文章支持某一具体论断；记录查阅日期和访问范围。

没联网或没拿到作者指南时继续完成材料支持的写作，标出需要核验的引用和期刊规则。不要把“近五年”“20 篇”等经验值当成检索过滤硬条件，也不要为满足数量凑引用。

## 最终交付

默认先给正文，随后按需要给“主要修改”“材料缺口”“待核验事项”，无实际问题的栏目可以省略。单次输出受长度限制时，明确已交付哪些章节和下一处断点，不把截断文本标为完整稿。

图表任务交付规划、图注和可核实的检查结果；本模板库没有绘图或文档导出脚本。若用户另行要求实际制图或导出，依据当前可用工具完成，并分别报告文本检查、数据核对和渲染检查的实际范围。
