# SCI-DR.CAN

把作者已有的研究问题、方法、结果和文献组织成可供作者复核的论文草稿。核心是让研究问题、研究空白、方法、结果与贡献相互对应。

## 选择任务

- 用户指定章节、文字修改或审稿问题时，直接处理所选范围。
- 材料充足、任务明确的快速起草采用 Flash：提取必要信息，完成所需文本，再核查证据与表达。
- 整篇构建或跨章节重组采用 Pro：整理材料与论点，按写作顺序组织章节，再做全稿一致性检查。
- 只做投稿前检查时，输出问题及修改建议；不要自动重写全文。

先读 [输入与工作流](references/intake-and-workflow.md)，再按任务加载以下规则；不要为单章任务一次加载全部资料。

| 当前任务 | 加载规则 |
| --- | --- |
| 引言、研究空白、文献组织 | [引言](references/introduction.md) |
| 方法、实验设置、符号与公式 | [研究方法](references/methodology.md) |
| 结果叙述、原因分析、讨论与局限 | [结果与讨论](references/results-discussion.md) |
| 收束贡献、摘要与标题 | [结论／摘要／标题](references/conclusion-abstract-title.md) |
| 图表规划、图注、可读性与引用检查 | [图表与图注](references/figures-tables.md) |
| 修改稿、逐条回复审稿人 | [审稿回复](references/reviewer-response.md) |
| 定稿前核对、投稿前审查 | [质量检查](references/quality-checklist.md) |

整稿任务逐阶段加载相应规则；完成整稿或明确的质量审查前读取质量检查。需要解释规则来源、处理经验值或维护本 Skill 时，读取 [来源映射](references/source-map.md)。这些文件已包含执行所需规则，不依赖安装目录之外的笔记或其他 Skill。

## 始终遵守的边界

1. 写作指导不是研究证据。DR.Can 的教学例子、其他模板中的例子不能变成用户论文的研究事实。
2. 数据、方法细节、实验步骤、创新性和文献陈述须来自已提供且可读取的材料，或实际检索核验过的来源。不得补造样本量、指标、显著性、设备、文献或已完成的实验。
3. 保留已核对事实、作者提供但尚未核验的信息、解释性假设三者的区别。相关关系不自动证明因果；未显著或异常结果也应如实报告。
4. 缺失事实在正文标为 `[MISSING: specific information]`，中文说明逐项解释。材料冲突时列出来源与差异，不自行选择更有利的数据。
5. 目标期刊的实际要求决定字数、章节、编号与参考文献格式。没有拿到要求时采用通用学术格式，并列出尚未核对的项目；不要声称已满足某期刊规范。
6. 参考文献可保留作者提供的编号或引用键，但其真实性及对论点的支持未经核验时须单列说明。没有来源就标缺口，不生成看似完整的书目信息。
7. 输出用户需要的正文和必要说明，不输出内部推理过程。质量检查可以降低错误风险，不能证明论文一定录用或实验已经复现。

## 输出与文件

- 默认英文论文正文及英文审稿回复，中文解释、问题清单和修改建议；尊重用户明确指定的其他语言。
- 全文默认显示顺序为 Title → Abstract → Introduction → Methods → Results → Discussion → Conclusion → References；服从期刊规定，可合并 Results and Discussion，或省去无独立要求的 Conclusion。
- 只交付所请求的正文或 Markdown。除非用户要求保存，默认直接在对话中给出；需要文件时使用用户指定的位置，没有指定则另建任务输出目录，避开模板目录和原始材料。
- 不覆盖作者原稿；明确要求原位修改时按授权范围执行。若工作区存在 `DR.Can.md`，保持该来源文件只读。
- 已有充分材料和授权时连续完成，不为每个阶段增加确认步骤。只有关键歧义会改变事实或结论时才提出精简问题，同时推进不受影响的部分。
- 不把图表说明当作已生成的图片，也不把文本检查当作 DOCX/PDF 排版验收。

## 调用示例

- “使用 $sci-dr-can，根据这些方法和实验记录组织一篇英文论文初稿。”
- “使用 $sci-dr-can，只改这段 Introduction，保留引用编号，说明研究空白是否成立。”
- “使用 $sci-dr-can，分析这张结果表，区分可证明的结论和待验证解释。”
- “使用 $sci-dr-can，逐条起草回复信；要求增加的实验尚未完成。”
