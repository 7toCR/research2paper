# I. Introduction 引言

读者接收的第一信息：吸引观众。

假设随意命题：《用A技术助力国足进入世界杯》

我：国足的惨败现状（需要解决的痛点：组织、人员位置、应对策略、防守逻辑、训练提升等），AI技术的智能化体现（优化、节省人力、成本、提高指标、预测等），本文通过A技术，对国足的这些痛点进行了怎样的研究优化，取得了什么结果，进而实现了助力国足进入世界杯的可能性提升，对于其他球队或者运动赛事的借鉴指导意义。

老师：回答两个问题：

1. What is the research topic？研究主题。
2. What is the motivation？研究动机【a. 重要性，宽泛 → 具体；b. 空白】。

用第二个问题来对第一个问题做合理解释，建立一个逻辑体系引入读者。

包括三个部分：

## a. Background information 背景介绍——突出话题的重要性

【可以从一个宽泛的话题入手，逐步走入研究话题中，可以有数据、陈述、现象】

E.g. 世界杯是最受关注的体育赛事，根据 xxx 报道[1]，每届都有 xxx 球迷到场，产生了 xxx 的经济价值……文化影响、政治影响，丰富世界杯的内容。

【缩小范围】

E.g. 国足承载了广大中国球迷的希望，2002年曾打入过世界杯，（历史回顾……），当天的消费增长、人们的激情昂扬、活动的热烈[2]……但自那以后，连续四届，铩羽而归。

## b. Literature review 文献综述——引出研究空白

【通过别人的成果/研究，引出学术研究空白，本文的研究填补这一空白】

E.g. 为了使国足重现辉煌，各方都做出了努力[3]，比如足协制定了一系列的特色政策，比如中小学推广的足球课程……但AI技术在这一领域的应用不广。

AI技术发展迅猛，在各个领域都有应用，比如 AlphaGo。

## c. Thesis statement 课题阐述

本文研究了A技术助力国足的可能性，并提出一种 xxxx 方法，进行了一种什么样的实验。本文的结构分别如下，后面几段分别介绍了什么。

## 建议

1. 可以多试试这类天马行空的话题，尝试写写引言。
2. 多在引言引用近期的文献，5年内。
3. 选取合适的文献，建立逻辑是为了引导读者。
4. 加一张好看的图或者表在里面。
5. 占全文10%的篇幅。

## 老师的实践论文引言架构

《Advanced Engine Cooling System Subjected to Ram-Air Effect — Nonlinear Adaptive Multiple Input and Multiple Output (NAMIMO) Control》

两部分：冷却系统 + 控制方法。

引言部分：

1. 首先介绍了各个国家签署的关于车辆二氧化碳排放的一些协议，从这里入手讨论了碳排放的重要性；画风一转，转到冷却系统对排放的影响，介绍现有发动机冷却系统的一些弊端，比如会使发动机过冷，会使能耗增加等等。
2. 再引入新的电控器件冷却系统的概念，并给出了一个图形。
3. 然后用了一些篇幅去介绍其他学者在控制理论上的贡献，引出了想讲明白的话题。
4. 最后一部分是本文的主旨和后面的文章结构等。

# II. 期刊审稿人手把手教你写一篇SCI论文（1）——事实汇总【论文写作】

## Fact 1. Paper structure 论文结构

- 题目 Title
- 摘要 Abstract【浓缩精华】
- 引言/文献综述 Introduction / Literature Review【讲别人的故事，去引出自己的研究内容】
- 研究方法 Method【包括实验、算法、数学等】
- 结果/讨论 Result / Discussion【重点、透过现象看本质，从实验结果/数据中找到有意义的东西】
- 结论 Conclusion【阐述本文章的贡献】
- 参考文献 Reference

## 时间顺序安排

1. 【对于一个新的研究/课题，首先要分析解决】从研究方法入手。
2. 结果和讨论【得到结果后，进入到分析讨论的阶段】。
3. 结论【把讨论得到的认识总结成结论】。
4. 文献阅读【贯穿始终、涵盖整个流程，和其他学者进行对比，找到自己工作的独创性/闪光点，并把这部分内容形成到引言中】。
5. 题目/摘要【临提交之前，精雕细琢题目和摘要部分】。

## Fact 2. Review process 审稿流程

Start → Submit

1. 作者 / Author  
   编写、投稿。

2. 管理员 / Administrator  
   录入，检查 Author's Guidelines。  
   是否按照写作规则来写的文章，包括字数、标准格式（此项不符可直接拒稿）。

3. 主编 / EIC（Editor in Chief）  
   查重、指派责编（Associate Editor）。

4. 责编 / AE  
   初审、寻找审稿人（同行审查，Reviewer / Peer Review）。

5. 审稿人 / Reviewer  
   3–5个，审核、打分、评语、建议。  
   先看标题和摘要确定是否审核（1周），确定再审查全文（2周）。

   打分标准：
   1. 原创性、重要性；
   2. 科学性、准确性；
   3. 文章表达；
   4. 细节。

6. 责编 / AE  
   总结审稿意见。

7. 主编 / EIC  
   Accept / Reject，或进入修改。

### 修改类型

- 小修 / Minor Revision：文章整体内容问题不大，要根据返回意见做些修正。
- 大修 / Major Revision / Reconsider / Reject & Resubmit：文章大的修改，包括结构、实验、结论等，可能经过几轮。

## Fact 3. 文章的第一印象（主观）

图表的美观：

1. 图结构清晰明了、具象化、色彩搭配合理、重点突出、指代明了。
2. 表所含信息丰富、指标多且合理。

## 参考文献

### 数量

- 8–12页文章：20篇左右文献数量正常。
- 综述：40–60篇。

### 时间

选取高质量的、比较新的文献。

# III. Methodology 研究方法

研究方法应该是最开始动笔的部分。

好写：最容易言之有物的章节，属于陈述性内容，流水账地记录过程。

不好写：难点在于研究内容 Contribution。

不同文章类型，这一部分差别较大：

1. 理论型：推导过程。
2. 实证型：调查方法、数据处理的手段。
3. 工程应用类（理论—实践）。

主旨：目的是向读者解释说明作者是如何得到这一结果的。

隐含条件：在条件允许的情况下，读者是可以通过作者的路径来复现结果，包括推导数学模型、模拟结果、实验结果。

要求/基本原则：

- 提供足够的、准确的技术细节【假设条件、数学推导、验证、实验设备等】；
- 简洁、清晰明了的逻辑表达【寻找领域里不错的论文，照猫画虎！】。

## 老师论文实例参考：研究方法内容

### 第二章 数学模型

数学模型所做内容 + 假设条件 + 系统的动态数学模型建立，构建模型所需的每个元素。

### 第三章 控制方法

提出了一个多输入多输出系统 + 稳定性分析 + 参考值选取 + 输入值调整。

### 第四章 实验设备

## 需要注意的点

### 1. 符号命名的一致性

容易混淆的地方使用下标，可以在写作一开始就建立标准符号的表格 Nomenclature，包括：

- 符号；
- 单位；
- 含义描述。

符号第一次出现时，要在文章中描述解释。

### 2. 公式的编号

数学推导中常见：

“substitute Eq. (xxx) into Eq. (xxx)”

推荐用 LaTeX 格式进行编辑，代码可以自动更新；用 Word 可能出错。

【1、2两点影响文章录用，审稿人会验证公式是否正确，而符号/公式乱用会使文章不可读。】

### 3. 不要灌水！

1）无关的内容：没有联系的公式、背景。

【判断是否无关，看研究结果是否用上这个内容，比如公式后续推导是否引用，实验中是否引用。如果相对独立，则考虑删去，或者移到引言处。】

2）基础内容。

基本常识性公式，比如牛顿第二定律 F = ma。

把大的篇幅留给后面的重要结果和讨论中。

# IV. Result & Discussion 结果与讨论

这部分是论文的核心，集中体现了作者的学术水平。学术大牛能把一样的结果变得点石成金，而不是肤浅的文字游戏。

如何做好这部分？需要长期大量的科研阅读、写作和系统的科学训练，没有捷径与速成。

入门模板：“结果 + 讨论”写作模式：

a. 描述结果  
b. 分析结果  
c. 讨论结果

视觉语言：图 & 表。

## 例子：B站后台粉丝数据

### S1：描述结果

统计结果表明，关注 DR_CAN 视频的主要人群年龄在16岁到25岁之间，占总粉丝人数的61.78%；随后是25到40岁的人群和40岁以上的观众。最少的是16岁以下的观众，这部分只占到总关注人数的7.11%。

定量 + 定性。

描述结果语言部分包含定量和定性描述两部分：

- 定量：具体数据指标，例如61.78%；
- 定性：总体属性、趋势，是从宏观角度来说的，例如“主要人群”“最少的”。

### S2：分析结果

UP主讲解的内容涉及了现代控制理论、非线性控制理论。16岁以下的人群基本属于高中阶段以下，这个年龄段的同学还在学习通用的基础课程。此外，UP主的视频当中用到了高等数学、线性代数、复变函数等数学工具，这些数学基础都是大一或者大二的课程，对于16岁以下的人群来说，接触的机会比较少。

论证 + 对比论证：

- 论证：分析结果的产生原因；
- 对比：通过对比不同年龄段的表现和区别，结合背后的原因进行分析。

### S3：讨论结果【Critical Thinking，要有深度】

这一年龄结构的统计数据验证了UP主做视频的初衷，视频的主要受众人群是高年级本科生、硕士博士研究生。半数以上的关注人群来自这一年龄段，也同时证明了UP主的作品内容没有跑偏。相信保持这样的内容和质量，这一数据将得到巩固，因为每年都会有新的学生接触到这一课题。

而另一方面，有70多个（7.11%）16岁以下的观众关注了UP主的视频，这可能是因为有些网友在注册时没有使用正确的身份信息。有很多网友都会选择注册当天作为自己的生日信息。

意义：论文的结果是如何印证你论文的意义和贡献。比如在论文中提出了新的算法，那么结果就应该能说明该算法很好，就可以说：“本文提出这一 xx 新算法很好地验证了计算结果的准确性。”

展望：扩展现有成果的应用领域，推至未来的方向。

猜想和假设：对于结果中的一些看起来并不那么正确的内容，不要试图去回避。即使回避，审稿人也能看出来；而是要给出自己的猜想，去想办法自圆其说，给出自己认为合理的解释。

## 注意

1. 第三部分，三个维度可以都讲，也可以只抓住“意义”一个维度分析到极致。
2. 重复上面两步，推广到其他结果的分析。
3. 注意详略得当，突出重点。要分析的结果可以大篇幅分析，不重要的可以合并到一起写。

# V. 图表

图表的重要性：第一时间浏览 & 第一印象。在审稿人指出问题前解决。

容易出错的地方：

### 1. 制图制表前，应该先参考期刊审核的要求

Author's Guide、期刊投稿要求、论文模板、标题和序号的规范。

一般地：

- 图用阿拉伯数字；
- 表用罗马数字；
- 图的标题在图的下面；
- 表的标题在表的上面；
- 看清楚期刊要求使用 Figure 还是缩写 Fig.

### 2. 所有的图表必须要在文中提到

多发生在引言部分的概念图。

### 3. 提到图表时，一定要引用图表的标号

比如：

“According to Fig. 7, xxxx.”

“Table III indicates that xxxx.”

避免：

“The above figure …”

“Refer to the table on the left …”

### 4. 一致性

图表中的表达方式要与论文中的一致，尤其注意检查符号和单位。

例如：图片中用的斜体符号，论文中也得用斜体表示。

### 5. 标题清晰、准确、完整

不要担心过长。

### 6. 用颜色和图例区分多数据

避免因黑白打印导致图中曲线混淆。

不要试图用混乱的图形去掩饰、隐藏不好的结果。有的不好的结果，反而值得探讨和猜想。

### 7. 多图对比

多图对比时，单图下面要有副标题/小标号进行区分，一般用小写英文 + 括号表示。

### 8. 杜绝一图多投

即便是同一作者、同一研究，投不同期刊时也要作一定修改。若非得要用同一张图，必须要加引用。

保留好原始数据，即使不写在论文中，以应对审稿人的修稿意见。

# VI. Conclusion、Abstract & Title

## Conclusion 结论

结论在结果和讨论之后，总结为1–2段。

开头：介绍本文主题和所用方法。

- 不要重复 Result。
- 对 Discover（发现）、Extension（扩展）、Future Plan（未来）进行汇总。
- 不要简单地复制粘贴，要改写。
- 改写可通过 thesaurus.com、zh.powerthesaurus.org 进行同义词替换。
- 强调所做内容的 Contribution（贡献），并与 Introduction（引言）部分相对应。

把 Result & Discussion 汇总，但要改写，不要 Copy & Paste。

Contribution 和 Introduction 对应。

## Abstract 摘要

学术文章不能文不对题。

Abstract 摘取文章要点。写之前要求引言、研究方法、结果与讨论、结论都已经写好。

1. 引言：提炼三句话，引出研究话题，强调研究的重要性。
2. 研究方法：1–2句话，核心、简要地概括。
3. 结果与讨论：只选取最重要的结果来描述，可以有数据，但一定要非常重要，比如采收率提高 xx。
4. 结论：改写，强调文章贡献。

1）和4）：贡献和重要性。  
2）和3）：所做内容。

## Title 题目

包括：

研究内容 + 研究方法 + 结果。

结果可以不放；如果放，可以用隐含的词：

- 提升 / 改善 / 优化：Improvement
- 减少 / 降低：Reduce

要求包括所有关键词。

# VII. 回复审稿人 + 建议

## 回复审稿人重要原则

1. 保持良好心态，以应对审稿人返回的修改意见。  
   无论大修小修，只要不是直接拒稿，就是好事。

2. 认真地逐一回答每一条审稿意见。

3. 直接、清晰地在文章和回复信件中标明所有修改。  
   比如，备注上所有修改内容，用高亮标注。

   示例原文中可辨识部分：  
   “Each comment will be directly addressed regarding the modified manuscript with changes highlighted in yellow.”  
   其后截图示例文字存在较严重OCR乱码，无法从现有文本可靠还原，故不擅自补写。

4. 礼貌、客气，感激编委的建议和时间。对于存在不同意见的表达，也需要委婉。

## 建议

### 1. 有哪一类的问题是很多 Reviewers 都会提出来的？

1）文字格式、图表样式的修改意见。

整个文章研究的背景，涉及文章 Abstract、Introduction 和 Conclusion 的修改。

2）审稿人会提出添加引用文献的要求：

- 可能忽略了一些比较重要的工作；
- 慎重地对待，加入相关的讨论；
- 有时审稿人希望作者引用自己的文章，增加被引量，有用才引用。

### 2. 遇到过最难回答的问题是什么？怎么回答的？

1）创新性相关的问题：

内容有人做过，方法虽然新，没有实验数据支持【对文章贡献的否定】。

要求作者与导师深入探讨，回顾自己在研究过程中的结论并发掘价值。

2）实验细节问题：

加、补实验。

3）如果实验因为客观原因不能完成：

- 尽量设计其他方案，提供其他的实验结果来解释审稿人的问题；
- 说明实验困难（比如有文献说明）；
- 无法实现时，用其他证据证明文中提出的观点。

### 3. 审稿意见的回复需要多长时间？

一周到一个月不等。

### 4. 审稿人必问的问题是什么？

1. 文章背景相关的问题；
2. 整个领域的贡献；
3. 与重要文献的关系、比较；
4. 文章的图；
5. 文章的创新性；
6. 引言拓展不够，很多作者不重视 Introduction 部分；
7. 实验细节；
8. 结果讨论中说的每一句话，都应该有实验数据或者已发表的工作作为支撑证据。

### 5. 文章中直接拒稿的原因？

1. 明显的数学、工程常识错误；
2. 明显的剽窃；
3. 错字错词过多，图表潦草；
4. 一稿多投，数据雷同；
5. 声称没有人用过的方法，是不是真的没有人用过；
6. 图片信息量不足、灌水；
7. 明显不专业的表现。

### 6. 会对什么文章有好感？

1. 描述问题清楚，方法记录有逻辑并全面；
2. 算式格式标准，图表数据清晰；
3. 模拟、实验具备；
4. 图片整齐、信息量足，逻辑清晰，证据确凿，能够自圆其说；
5. 对于返修稿，重看作者有没有认真地、尽力按审稿人的要求修改。

### 7. 关于“怼回去”（尽量不怼）

1）要求很高的好杂志，审稿人会吹毛求疵，随意拒稿。

2）编辑的态度，如果编辑欣赏……【此处原OCR文本不完整】。

- 把所有审稿人提出的合理审稿意见都认真地回答好，补充数据，把被指出的漏洞补上。
- 对于那些明显不合理的审稿人（只批评、没建议），结合其他审稿人的意见来反驳。
