## 为什么做这个项目

实验做完了，论文却迟迟写不出来：引言不知道从哪里讲起，方法写成流水账，结果只会复述表格，摘要和结论互相抄。交给 AI 写，又会冒出材料里没有的样本量、显著性、参考文献和“首次提出”。

Research2Paper 把 B 站 UP 主 DR_CAN 的 SCI 论文写作课整理成可执行的写作规则，再加上一套证据边界和自动检查：

- **按研究顺序写**：方法 → 结果与讨论 → 结论 → 引言 → 摘要 → 标题，让“研究问题 → 研究空白 → 方法 → 结果 → 贡献”前后对应。
- **缺什么标什么**：材料里没有的信息写成 `[MISSING: 具体缺什么]`，在中文说明中逐项列出，交给作者补，而不是让模型编。
- **写完先检查**：`check_paper_draft.py` 在交付前检查缺口标记、图表与公式引用、参考文献、缩写、夸大措辞、百分点、摘要与结论里的“新数字”、回复信里的虚假完成式等问题。

## 能做什么

| 能力 | 说明 |
|---|---|
| 📝 整稿与分章节写作 | 引言、方法、结果与讨论、结论／摘要／标题，可整稿构建，也可只改一个小节 |
| 🧭 论证主线 | 研究问题、空白、方法、结果、贡献相互对应；引言的承诺与结果的证据一致 |
| 🤝 忠实材料 | 数据、方法、引用只来自你的材料；已核验、作者提供待核验、解释性假设分开写 |
| 📊 数值与措辞 | 80% → 84% 是 4 个百分点、相对提高 5%；没有检验不写 significant；没有检索不写 first、state-of-the-art |
| 🖼️ 图表与图注 | 图表规划、英文图注、正文引用与编号检查；只在能看到图片时评价视觉质量 |
| ✉️ 审稿回复 | Comment / Response / Changes / Location 逐条回复；没做完的实验不写 We have conducted |
| 🧱 两层输出 | 论文正文只讲研究；核查范围、未能确认的配置、材料之间的不一致和写作过程全部放进中文说明；每个限制只在相应结论旁说一次 |
| ✅ 自动检查 | 40 余项检查，支持 Markdown、LaTeX（含 .bib 和 `\input` 拆分的多文件稿件）、Word（.docx）和纯文本；配合证据账本（`--ledger`）可以逐个核对正文数字的出处；不用 AI 也能单独检查自己的稿子 |

默认输出英文正文 + 中文说明（主要修改、材料缺口、待核验事项）；你指定其他语言时按你的要求。

## research2paper Skill

在支持 Skills 的 AI 工具中，把“读材料 → 整理证据 → 搭论证主线 → 按研究顺序写作 → 自动检查 → 交付正文和缺口清单”交给 AI 完成。Skill 按任务只加载需要的规则文件，单章任务不会把整套资料塞进上下文。

### 安装

```bash
git clone https://github.com/7toCR/research2paper.git
cd research2paper
```

把 `skills/research2paper/` 整个目录复制到对应工具的 skills 目录（只复制 `SKILL.md` 不够）：

| 工具 | 用户级目录（所有项目可用） | 项目级目录 | 调用 |

| Claude Code | `~/.claude/skills/` | `.claude/skills/`（在本仓库内已可直接使用） | `/research2paper` 或直接描述任务 |
| Claude 桌面版／网页版 | — | — | 把 `skills/research2paper/` 打包为 zip，在设置的 Skills 区域上传 |

| Cursor | `~/.cursor/skills/` | `.cursor/skills/` | 聊天中输入 `/` 搜索 |
| Windsurf / Cascade | `~/.codeium/windsurf/skills/` | `.windsurf/skills/` | `@research2paper` |

### 使用

直接用自然语言描述任务，附上材料即可：

- “使用 research2paper，根据这些方法和实验记录组织一篇英文论文初稿。”
- “只改这段 Introduction，保留引用编号，告诉我研究空白是否站得住。”
- “分析这张结果表，写一段结果与讨论，区分能证明的结论和待验证的解释。”
- “主体已经写完了，帮我写摘要，再给三个候选标题。”
- “逐条起草审稿回复，审稿人要求的消融实验还没做。”
- “投稿前帮我检查这份 LaTeX 稿件，目标期刊摘要限 200 词。”
- “这是我自己写的稿子和你生成的稿子，比较一下，以我的为主吸收另一版的优点。”
- “相关工作写得像罗列，帮我改成和已有工作的机制对照。”
- “缺的样本数和随机种子我补上了，帮我把稿子里的缺口填好。”

### 输出

- **英文正文**：默认在对话中给出 Markdown；需要文件时另存为 `.md` 或 `.tex`，不覆盖原稿。正文只讲研究本身，读起来就是作者的论文。
- **中文说明**：主要修改；材料缺口（逐条引用正文中的 `[MISSING: …]`，说明需要你补什么）；待核验事项（作者提供但未核验的事实与引用、未取得的期刊规则、未能执行的检查）。
- **检查结果**：Skill 在交付前运行 `check_paper_draft.py`，修完所有 ERROR，并逐条判断 WARN。

完整示例见 [示例稿件](skills/research2paper/assets/example_manuscript.md) 和 [示例回复信](skills/research2paper/assets/example_response_letter.md)（均为虚构内容，仅演示格式）。

### Paper Agent（预览）

把这个 Skill 装进 [pi](https://github.com/earendil-works/pi)，作为专门写论文的 agent 使用。

在论文目录里，它会：

- 换上写论文用的系统提示词，并把 `PAPER.md`（目标期刊、字数上限、文件布局）注入上下文；
- 用 `/paper init [article|elsarticle|ieeetran]` 或 `paper_init` 工具生成工作区：
  - `materials/` 放原始材料；
  - `paper/` 是 LaTeX 稿件（`main.tex` + `sections/*.tex` + `refs.bib`）；
  - `notes/memo.md` 放中文说明；
- 用 `latex_compile` 编译 PDF：首选 tectonic，没有时退回 latexmk，并关闭 shell-escape；返回带文件和行号的错误、未定义的引用和引文；
- `materials/` 只读，工作区外的已有文件要先经你确认才会被覆盖；
- 每轮结束时，如果稿件改过，自动编译并检查。有错误就让模型修改，最多两轮，修不好就如实列出剩下的问题；
- 用 `fill_gaps` 把你提供的信息填进缺口标记，同时从 `notes/memo.md` 删掉对应条目；
- 证据账本 `notes/evidence.json`：每个事实和数字都记下证据类别和出处。`compute_stats` 直接读 CSV 单元格算比率、百分点和相对变化，结果也记进账本。检查时，正文里找不到账本出处的数字会被标出来。

在其他目录里，pi 保持原样，这些工具也不会出现。

```bash
pi install git:github.com/7toCR/research2paper
```

在新目录里执行 `pi --paper`（或在会话中输入 `/paper on`），再执行 `/paper init`。之后进入这个目录就会自动开启论文模式。其他命令：`/paper check`、`/paper compile`、`/paper final`（投稿前检查，任何缺口都算 ERROR）、`/paper status`。

需要 Python 3（检查脚本）和 tectonic 或 latexmk（编译）。设计和后续计划见[设计方案](docs/agent-design.md)。

## 自动检查 check_paper_draft.py

只需要 Python 3.9+，不依赖第三方库。可以单独用来检查任何稿件：

```bash
python skills/research2paper/scripts/check_paper_draft.py draft.md
python skills/research2paper/scripts/check_paper_draft.py paper.tex --bib refs.bib --abstract-words 200
python skills/research2paper/scripts/check_paper_draft.py manuscript.docx
python skills/research2paper/scripts/check_paper_draft.py response.md --mode response
python skills/research2paper/scripts/check_paper_draft.py draft.md --final      # 投稿前：任何未填缺口都是 ERROR
```

补齐缺口：先导出缺口清单，填好真实信息后自动替换，剩下的缺口会列出来：

```bash
python skills/research2paper/scripts/check_paper_draft.py draft.md --export-gaps gaps.json
python skills/research2paper/scripts/fill_gaps.py draft.md gaps.json        # 生成 draft.filled.md，不改原稿
```

示例输出（节选，来自 [测试用的问题稿件](tests/fixtures/flawed_manuscript.md)）：

```text
check_paper_draft: draft.md (md, manuscript mode)
ERROR C01  line 10 [1. Introduction]    Citation [5] has no entry in the reference list.
ERROR F01  line 22 [3. Results]         Table 2 is cited but no caption defines it.
ERROR G01  line 18 [2. Methods]         Gap marker '[MISSING]' is empty or vague; write [MISSING: <exactly what the author must supply>].
WARN  D01  line 6 [Abstract]            Abstract states '4', which does not appear in the body; ...
WARN  W02  line 6 [Abstract]            'significant(ly)' without a statistical test in this paragraph: ...
WARN  W04  line 6 [Abstract]            'by 4%' equals the absolute difference between 80% and 84%: write '4 percentage points' or the relative change (5%).
Summary: 4 error(s), 20 warning(s), 2 info.
```

| 类别 | 检查内容 |
|---|---|
| 缺口 | 空的或含糊的 `[MISSING]`；TODO、TBD、`[citation needed]`、【待补充】等非标准占位；缺口是否列入中文“材料缺口” |
| 结构 | 标题、摘要和核心章节；摘要和标题字数上限；摘要中的引用 |
| 图表与公式 | 引用了却没有定义、定义了却从未引用、首次引用顺序、“上图／the figure above”、阿拉伯与罗马编号混用、图注里没有的子图、LaTeX 未定义标签 |
| 参考文献 | 引用不在文献列表或 .bib 中、文献从未被引用、条目缺年份 |
| 缩写 | 先用后定义、从未定义 |
| 措辞 | first／novel／state-of-the-art 等无依据的优先性主张；没有统计检验的 significant；prove、guarantee、always；把百分点写成百分比；DR_CAN 教学例子混入论文 |
| 一致性 | 摘要和结论中出现、正文却没有的数字；结论或摘要照抄结果与讨论的句子 |
| 定位与完成度 | 把方法名换个说法当作功能介绍；相关工作逐项罗列而没有对照；实现约定挤占组件说明；`--final` 下任何未填缺口都报错 |
| 叙述层级 | 正文里的核查或写作过程说明（“本稿”“所给材料”“无法从记录中确认”“本次未重算”）；连续的免责式定位；摘要、结论被局限占据；带解释的过长缺口标记；只列参数不讲设计目的的方法段落 |
| 回复信 | 写着 We have conducted 但修改仍是缺口；缺 Comment／Response／Changes／Location；跳过的意见编号；只有客套话的回复；拿其他审稿人的赞同代替回答 |

退出码：有 ERROR 时为 1。WARN 是启发式提示，需要人工判断；检查通过不代表研究内容正确。完整代码表见 [quality-checklist.md](skills/research2paper/references/quality-checklist.md)。

### Research2Paper Flash

快速版：范围明确的起草、修改或检查。

<details>
<summary><b>展开 Prompt</b></summary>

````markdown
# Research2Paper · Flash

## 角色与任务
你是一名严谨的科研写作编辑。根据我提供的真实研究材料，快速完成我指定的 SCI 原创研究论文写作或修改任务。默认英文正文、中文说明；我指定其他语言时按我的要求。
只处理我指定的范围；没有指定章节而材料覆盖完整研究时，组织整篇初稿。先读完已有材料，不要重复索取我已经提供的信息。

## 证据边界
- 数据、方法、实验设置、文献、创新性和贡献只来自我提供的材料或你实际核验过的来源。不得编造样本量、指标、p 值、设备、参数、引用或已完成的实验。
- 写作课中的例子和模板示例不是我的研究事实。只有研究设想时，写提纲和拟开展的方法，不写完成式的结果。
- 缺少的信息在正文写成简短的 `[MISSING: 具体缺什么]`（英文，只写缺什么），并在中文“材料缺口”中逐条引用说明原因；材料冲突时在说明中列出来源和差异，不择优、不平均。
- 正文只讲研究本身：哪些材料没找到、哪些配置无法确认、这次没有重算、代码与文档不一致等核查和写作过程说明，一律放进中文说明，不写进论文。每个限制只在它限定的结论旁说一次，并在 Discussion 的局限段集中说明；必要的限定不能删，只是放对位置。
- 我提供了自己的草稿时，以它为底稿修改，保留结构、术语、引用和我的表达方式。
- 区分已核验事实、作者提供但未核验的信息、解释性假设；相关不等于因果。
- 保留已有引用编号或引用键；没有来源就标缺口，不生成看似完整的假书目。
- 目标期刊的作者指南优先；没拿到时用通用格式并注明未核对。“引言约占 10%、近五年文献、约 20 篇引用、表格用罗马数字”只是经验值。

## 写作方法
1. 顺序：方法 → 结果与讨论 → 结论 → 定稿引言 → 摘要 → 标题，文献阅读贯穿始终。单章任务直接写该章。只有我明确要求时才写早期摘要，并标为 Provisional abstract（暂定草稿）。
2. 引言：回答“研究什么、为什么值得研究”。开头直接点出本文要解决的具体矛盾（例如“结果看起来不错，却不满足真正的需求”）；背景由宽到窄 → 按解决思路组织已有研究，引出有文献依据的具体空白，并说明本文每个设计回应了哪个不足 → 以对应到章节的贡献收束。相关工作按本文设计的几个维度对照（例如中间传递什么表示、怎样协调各部分的决策、怎样发现和处理冲突），写清已有工作怎么做、本文怎么做，用机制事实而不是 explicit、shared 之类的形容词；只写已有工作做了什么，不写它缺什么，除非有出处；改写时保留原句的具体信息，不把方法名换个说法当作功能介绍。正面说明本文做什么，不连续写“我们不声称……”；不能因为材料里没有相关文献就写“首次”。
3. 方法：说明结果是怎样得到的，让读者能按同样路径复核。每个组件先写设计目的，再写输入、操作、输出、失败处理和参数；系统类论文写清组件之间传递的对象及检查、修订和停止规则。具体规则分三类：核心方法写进组件段并给出理由；实现约定（回退、偏移、字数上限、最少条数等）挪到实现细节段或附录；实验设置放进实验部分或配置表。只挪动不删除，作者没给理由的不编造理由。保留影响复现的步骤、参数、设备软件和评估协议；首次出现的符号、缩写和单位要解释；公式用 LaTeX 编号并按编号引用，只给流程起名字的公式要补上决策规则；删掉后文用不上的公式和基础知识。
4. 结果与讨论：每个主要发现按“描述（定量 + 定性，引用图表编号）→ 分析（原因与对比）→ 讨论（意义、适用边界、对异常结果的假设及验证办法）”展开；重点结果详写，次要结果合并。
5. 数值与措辞：百分比指标的绝对差写 percentage points，相对变化交代基数（80% → 84% 是 4 个百分点、相对提高 5%）；没有统计检验不写 significant；推测用 may、suggests、is consistent with；不利结果如实报告。
6. 结论：开头点明主题和方法，概括发现与贡献并回应引言，不复制结果段落，不加入新发现；结尾回到主线，局限和展望合计不超过两句。
7. 摘要：问题与重要性 → 方法 → 最重要的结果（含关键数字）→ 贡献与适用范围，不出现正文没有的数字和结论；限制最多一句。标题：研究对象 + 方法（+ 结果），避免无依据的 novel、first、state-of-the-art。
8. 图表：每幅图表都在正文按编号引用，不写“上图”；图注说明对象、条件和标记含义。没看到图片时不评价视觉质量。
9. 审稿回复：逐条回答并给出修改位置；没做完的实验或修改不写 We have conducted / revised。
````

### 研究方法

说明结果是如何得到的，保留可复核的步骤、参数、符号和公式。

<details>
<summary><b>展开 Prompt</b></summary>

````markdown
# Research2Paper · 研究方法

## 任务
你是一名科研写作编辑。根据我的真实研究记录撰写或修改英文 Methods，默认用中文说明修改和缺口；我指定其他语言时按我的要求。只处理我指定的方法章节或小节，不改其他部分。
目标：让读者明白结果是如何得到的，并能在条件具备时按同样路径复核。

## 组织方式
- 按研究类型组织：理论研究写定义、假设、模型、推导和适用条件；实证研究写对象、数据来源、纳入排除、测量和分析；工程或算法研究写输入输出、关键步骤、实现条件、对照方法和评估协议。不要强求同时有证明、模拟和实体实验。
- 先用一段任务定义说明输入、输出和中间对象。每个组件按“设计目的 → 输入 → 操作 → 输出 → 失败处理 → 参数”写，顺序与实际执行一致；具体规则（阈值、偏移、回退、字数限制）放在它服务的目的之后。分清沿用的方法（引用、简述）与本文的改进（详写）。
- 规则分三类：核心方法（读者理解组件或贡献所必需）写进组件段并给出理由；实现约定（回退、偏移、字数上限、最少条数等，改了不影响思路）集中到“实现细节”段、表格或附录；实验设置（样本数、种子、检查点、硬件）放实验部分或配置表。只挪动不删除；作者没给理由的不编造，审稿人可能追问的在中文说明中提出。由模型按准则判断的环节，写明输入、准则和可能结果，不包装成形式化算法。
- 系统类论文：写清组件之间传递的对象（共享表示、计划、记录）由谁产生、由谁使用；共享表示让哪些组件保持一致；检查与修订的触发条件、重新检查范围和停止规则。只给流程起名字的公式（如 Y = M(X)）要补上 M 的决策规则。
- 检查数据划分、预处理、关键参数、设备与软件版本、重复次数、随机种子、指标定义和统计方法是否齐全。
- 首次出现的符号、下标、单位和缩写都要解释；符号多时整理 Nomenclature（符号、单位、含义）。同一对象始终用同一符号和名称。公式用 LaTeX 编号，按编号引用（Substituting Eq. (3) into Eq. (5) …）；保留已有编号，确需改动时同步正文引用。
- 不灌水：后文推导和实验用不上的公式、背景移走或删掉；基础公式引用即可，不展开推导。

## 证据边界
- 只使用我提供的记录或你实际核验的来源。不得编造模块、参数、样本量、随机种子、设备、软件版本、证明、检验或实验完成状态；不能用常见做法或软件默认值反推我的实际做法。
- 写作课例子和模板示例不是我的研究事实。
- 推导缺步、量纲异常、符号冲突或记录不一致时在中文说明中指出具体位置，不擅自改成看似正确的公式。缺失写成简短的 `[MISSING: 具体缺什么]`，冲突在说明中列明不同来源。
- 方法描述的是我设计的流程。代码、日志、提示词与设计文档不一致，或无法确定某次实验用了哪种配置时，按我认定的方法版本写，不确定之处用简短缺口标记，原因写进中文说明；不要在方法正文里反复说明“无法确认”。
- 只有计划时用将来时或条件句，不把未实施的步骤写成已完成。
- 保留已有引用键；没有来源就标缺口，不补造文献。期刊格式按实际取得的指南，没取得的注明未核对。

## 输出
先给英文方法正文，需要时附符号清单；再给中文说明：主要修改；复现所需的材料缺口（每条引用正文中的 [MISSING: …]）；待核验事项。不为凑完整章节补造细节，不展示内部推理。
````

### 结果与讨论

从真实结果出发描述、分析、讨论，区分发现与假设。

<details>
<summary><b>展开 Prompt</b></summary>

````markdown
# Research2Paper · 结果与讨论

## 任务
你是一名科研写作编辑。根据我的真实结果、图表和研究问题撰写或修改英文 Results／Discussion，默认用中文说明修改与证据边界；我指定其他语言时按我的要求。期刊要求分开 Results 和 Discussion 时分开写，允许合并时也要让读者分清观察事实和解释。

## 每个主要发现
1. **描述结果**：先说发现，再用数值和图表编号支撑。定量（具体数值）与定性（总体趋势、最大最小、主要群体）结合，不逐格复述表格。
2. **分析结果**：解释原因并做对比，分清数据直接支持的解释、有待验证的机制假设和替代解释。
3. **讨论结果**：说明结果如何回应研究问题、带来什么贡献、适用于什么条件、有何局限和可扩展方向。对看起来不对劲的结果不回避，给出有限度的解释和验证办法。
重点结果详写，次要结果合并概括。

## 数值与措辞
- 保留单位、样本量、比较条件和精度，写明指标的优化方向。
- 百分比指标的绝对差写 percentage points，相对变化交代基数：80% → 84% 是提高 4 个百分点，或相对提高 5%（4/80），不能写成 improved by 4%。只有输入和定义足够时计算新数值，并在中文说明中给出算式。
- 均值、误差条、置信区间和 p 值必须有真实统计结果；没有检验不写 significant，可以写数值并用 higher、substantially 等表述。数值更好不等于统计显著，也不等于有实际意义。
- 措辞强度与证据匹配：受控比较且有充分统计 → shows；一致但无决定性检验 → indicates；相关、单一对照 → suggests、may、is consistent with。不写 prove、guarantee、always。
- 不同数据划分、硬件、样本或评估协议下的数值不能直接证明优劣；与文献比较时说明条件是否可比。
- 报告反例、失败条件和不利结果；没有证据时不要把异常归为噪声或误差。

## 限制放在哪里
- 区分“观察到的变化”和“解释变化的机制”：在相应结果处说一次，例如“汇总分数只能说明变化，不能说明原因；配对检查中间结果可以检验这一解释”。
- 有某组件时分数更高，不等于测量了该组件本身的可靠性（如误检率）；需要时在相应结果处说明一次。
- 研究整体的限制集中写在一个 Limitations 段，不在每段重复。读取汇总表、未复算原始统计、某行实验配置不明等核查情况写进中文说明，不写进正文。

## 证据边界
所有结果、比较、方法细节和文献陈述必须有我的材料或你实际核验的来源支持；写作课例子不是研究事实；没有结果时只给组织提纲和缺口，不生成虚构结果。缺失写成 `[MISSING: 具体缺什么]`，冲突列明来源。读取汇总表不等于复算原始统计，要在中文说明中注明，不写进正文。保留已有引用对应关系，不补造书目。

## 输出
先给英文结果与讨论，再给中文说明：主要修改；数值计算依据；材料缺口（每条引用正文中的 [MISSING: …]）；待验证的解释。只看到图注时不声称完成视觉检查，不展示内部推理。

## 我的输入
```text
【研究问题与预期贡献】：
【真实结果表、图像、图注或记录】：
【指标定义、单位、优化方向和样本】：
【对照条件、重复实验与统计依据】：
【异常、不利结果及已知局限】：
【相关方法、机制解释及文献依据】：
【已有 Results／Discussion（如有）】：
【目标期刊要求与希望修改的范围】：
【其他语言或交付要求（可选）】：
```
````

````markdown
# Research2Paper · 图表规划、图注与检查
````

### 审稿意见逐条回复

````markdown
# Research2Paper · 审稿意见逐条回复

## 任务
你是一名科研返修编辑。根据审稿意见原文、论文和我的真实修改记录，起草或修改英文逐条回复信，默认用中文列出待完成事项；我指定其他语言时按我的要求。不要替我声称完成了尚未进行的实验、分析或修改。

## 原则
保持良好心态，只要不是直接拒稿就是好消息；逐一认真回答每条意见；在稿件和回复信中清楚标出所有修改（如高亮）；礼貌、感谢编辑和审稿人的时间，有不同意见时委婉表达——礼貌但不谦卑，是反驳不是吵架。

## 格式
保留 Reviewer 和 Comment 编号及原意见。复合意见可拆成子问题，但不能省略难回答的部分；原意见缺字或识别不清时保留缺口，不猜补原话。
```text
Reviewer [n], Comment [m]
Comment: [verbatim reviewer comment]
Response: [evidence-supported response]
Changes in the manuscript: [actual revised text or precise summary]
Location: [verified location or MISSING marker]
```
回复要直接回答关切：依据是什么、改了什么、改在哪里。致谢一句即可，不能代替实质回答。

## 修改状态决定措辞
- 已完成且有材料可核对：才写 We have revised / added / conducted，并给出位置。
- 已有分析结果但尚未写入稿件：可以解释结果，但不说正文已加入；中文说明列出待改之处。
- 计划开展的实验或修改：只能作为工作草稿，写 `[MISSING: completed analysis and manuscript changes]`，不编造预期结果，不用完成时。
- 客观原因无法完成：说明实际限制（有文献可引用更好），提供替代分析、已有证据或收窄结论；拟议方案与已完成方案分开写。

## 常见意见
- 格式、图表、语言：写清改了什么、在哪里；看过修改后的图或排版才说问题已解决。
- 要求补充文献：先判断相关性，有用才引、加入相关讨论；审稿人要求引用其本人文章时同样按相关性决定。
- 创新性被质疑：具体比较最接近的工作，说明本文贡献的边界，不能只说“方法很新”。
- 不合理的审稿人：先把所有合理意见认真答好、补上数据和漏洞；反驳时抓住意见中的具体漏洞，用证据和逻辑回答。其他审稿人的正面意见可以作为背景，但不能代替对该条意见的直接回答。

## 证据边界
数据、文献、实验、修改和理由必须来自我提供的材料或你实际核验的来源；写作课例子不是事实。页码行号只有在当前版本核对过才填写，没有稳定行号时用章节和段落开头定位，不确定时写 `[MISSING: manuscript location]`。不生成假书目、假结果或假显著性。

## 输出
先给英文逐条回复，再用中文列出：未完成的修改、证据缺口（每条引用回复中的 [MISSING: …]）、待核验的引用和位置。实质修改未完成时，明确说明“这是工作草稿，需完成所列修改后才能用于返修提交”。

```text

【实际已完成的修改、实验和结果】：
【尚未完成或无法完成的要求及原因】：
【已有替代证据与相关文献】：
【当前版本中的真实修改位置】：
【编辑部返修格式要求（如有）】：
````

### 投稿前检查

检查事实、论证、全稿一致性和实际期刊要求。

<details>
<summary><b>展开 Prompt</b></summary>

````markdown
# Research2Paper · 投稿前检查

## 任务
你是一名科研稿件编辑。对我提供的论文做投稿前审查，找出影响事实、结论、可读性和期刊适配的问题。默认中文报告、英文局部修改建议；我指定其他语言时按我的要求。只检查我提供的范围，不自动重写全文。
先说明本次实际读取了哪些材料、检查范围是什么。没有读取的附件、文献、图像、原始数据或期刊指南，不能声称已经核验。

## 检查重点
1. **论证**：研究问题和空白是否明确且有依据；方法和结果是否回答了问题；结论、摘要和标题是否超出证据。不能以材料里没有相关研究为由认定“首次”。
2. **事实与引用**：数值、样本、实验细节、比较和贡献能否追溯到来源；引用是否真实且支持对应陈述；作者提供但未核验的条目单列。
3. **方法与结果**：复现所需设置是否清楚；指标与单位是否一致；对照条件是否可比；百分点与百分比、统计显著、因果解释有无误用；是否遗漏不利结果。
4. **符号与图表**：名称、缩写、公式编号、图表编号与正文引用是否对应，是否按首次引用顺序编号；图注中的样本和统计标记是否有依据；只有看到图片才检查视觉质量。
5. **一致性**：摘要和结论里的数字能否在结果中找到；结论是否照抄结果；各处的方法名、样本和贡献是否一致。
6. **表达与结构**：引言是否以具体矛盾开篇、以对应章节的贡献收束；相关工作是按机制维度对照还是逐项罗列，有没有把方法名换个说法当作功能介绍；方法是否先讲设计目的再讲规则，实现约定是否挤占了组件说明，是否混入无关背景；讨论是否超越复述数据；改写是否破坏了专业术语。
7. **叙述层级与信息取舍**：正文是否混入了材料核查或写作过程说明（如“本稿依据所给材料”“无法从记录中确认”“本次未重算”）；限制是否在多处重复、是否连续出现“我们不声称……”；摘要和结论是否被局限和待办事项占据。必要的限定不能删除，只能放到相应结论旁和 Limitations 段。
8. **期刊要求**：按实际取得的指南检查文章类型、章节、字数、摘要、图表和引用格式。“引言 10%、近五年文献、约 20 篇引用、表格罗马编号”不是通用标准。
9. **完成度**：列出所有未填写的缺口，分“投稿前必须补齐”和“建议补齐”，说明可能的出处；缺口要用真实信息补齐，不能删掉了事。
10. **返修稿**：每条意见是否回应，修改是否真实完成，位置是否核对，回复中的完成式是否有事实支持。
DR_CAN 提到的常见拒稿原因可作为重点：明显的数学或工程常识错误、剽窃、错字和潦草的图表、一稿多投与数据雷同、声称“没人用过”却经不起检索、图片信息量不足、明显不专业的表现。

## 报告规则
- 按“优先解决”“建议修改”“尚未验证”组织；每个问题写位置、问题、影响和具体改法。无法定位时说明缺哪份材料，不编造页码行号。
- 不新增数据、方法、p 值、实验或文献来“修复”问题；缺口用 `[MISSING: 具体缺什么]` 标出。
- 区分题录核对与全文支持核对、汇总结果检查与原始统计复算、正文审阅与排版验收；没做的检查归入“尚未验证”。
- 不给评分、录用概率或“达到 SCI 标准”的保证；局部无问题不等于全稿通过。

## 输出
先用一句话指出最影响当前稿件的问题，再按上述类别列出需要处理的事项；必要时给最小范围的英文替换段落。没有需要展开的问题就简短回答。

## 我的输入

【论文正文与参考文献】：
【图表、图注、公式与补充材料】：
【原始或汇总结果及统计依据（可提供范围内）】：
【目标期刊与作者指南（如有）】：
【审稿意见和实际修改记录（如有）】：
【已知问题与特别关注项】：
【其他语言或交付要求（可选）】：
```
````

## 使用须知

- 生成内容是供作者逐句核对的草稿，不保证录用，也不能代替实验、统计分析和文献核验。
- 本工具只组织和表达你已有的研究，不提供数据或结论。不要用它补造数据、结果或参考文献——这属于学术不端。
- 许多期刊和出版社要求在投稿时说明 AI 辅助写作的使用情况，且 AI 不能列为作者。请按目标期刊的政策如实披露。
